### Highlights

- Open Chaxter in a browser: the web app reaches your Hub through a secure tunnel, with each browser registering its own device.
- A cloud console in Settings, with Home, Hubs, people, keys, integrations, mail, audit and subscription pages.
- The desktop app now keeps a tray icon: closing leaves it running, and the tray menu shows waiting requests and opens a new chat.
- Connect the desktop to a local or a remote Hub, pair it, switch between Hubs and watch the connection state.
- Terminals keep their own shell across reloads, reconnects and tab closes.

### Features

- Open Chaxter's web app in a browser and reach your Hub through a secure tunnel, with a device key registered per browser.
- Previews run inside the web app in the browser and are served through its own worker.
- A cloud console in Settings, with Home, Hubs, People, Keys, My access, Integrations, Mail, Audit and Subscription pages, drawn in Chaxter's own look.
- Each Hub has its own console page where you can rename it and see its users; the Home lists Hubs that stopped answering.
- Your company and name appear in the console top bar, and a cloud band sits above your sessions.
- See and revoke paired devices from Settings and from the console; a revoked device gets a screen that explains what happened.
- System-tray icon for the desktop app, with a close-to-tray switch, waiting requests in the tray menu and a shortcut to a new chat.
- Connect the desktop to a local or a remote Hub, pair a remote one and switch between them; a switch reloads onto the new endpoint.
- The connection band offers Retry, names the Hub's version and the device, and can redial on request.
- Start a new project from a GitHub URL, cloned by the Hub.
- A sandboxed Hub runs agent sessions inside its fence, offers only the agents it can start, and the dialog states the boundary.
- Sign the Hub in to the cloud with a magic link, claim ownership on first start, and reset the cloud identity from Settings.
- Settings › Cloud is laid out in titled groups, the cloud account reads as an account card, and the top bar shows it.
- A support page under Settings › Cloud, reachable from the Settings search and from the help menu, with the support address.
- Mail settings explain a refused sender, a refused envelope and a refused save.
- See your consultations of the last 30 days, read-only, with their audit entries and reasons written in your language.
- Per-repository GitHub tokens, and commits attributed to the cloud account that made them.
- The audit says what each entry is about and names the person who acted.
- Register the GitHub App once, from a pre-filled page.
- Releases now ship the web app and the console alongside the desktop build.

### Bug Fixes

- A reopened terminal tab takes its own shell, a new tab never steals a live one, and shells are kept per Hub.
- Closing a terminal tab ends only that tab's shell, and a terminal comes back to its shell after a reload or a reconnect.
- A terminal no longer waits for the agent to start before opening.
- Browser tabs renew their access before it lapses and reconnect by themselves after a refusal that is not final.
- A browser session that ends names its cause: revoked, expired, a skewed clock, or a Hub too old for the web app, which is told to update.
- Retry in a browser tab ends the waiting state at once.
- The console and browser tabs follow the language chosen on the cloud or in another tab.
- Previews read only as far as the player asks, say what to do when a page cannot be carried, and explain why a framed preview is not shown.
- Settings fits a 320 px window and 200 % zoom: the header collapses, the page picker reflows, and tables scroll in boxes of their own.
- An answer that arrives while you type leaves your field, your text and your focus alone.
- Confirmations, refusals and outcomes in Cloud are scrolled into view and hand the focus back to a named control.
- Cloud forms name the refused field in your language and keep what you typed.
- The Hubs list gives long names room to wrap, and says which Hub has stopped answering.
- The new-session dialog never defaults to an agent that cannot start, and its list closes on Escape.
- No "Scroll to bottom" button over a transcript that already fits its view.
- The top bar folds at every width, down to phone widths, with the workspace name giving way last.
- Band links bring the already-open Chaxter tab forward instead of opening another, and an ended tab gives up its name.
- Consultation views: panels that do not apply say so, dead links show no raw id, rows drop export and waiting strips, and a consultation opened from a link keeps its state.
- A Claude sign-in made through the Hub survives the next agent start, and a new account's first session survives a restart.
- The consultation view's scroll boxes and the one-time value boxes can be reached with the keyboard.
- On Windows the desktop builds again, and a shell that takes too long to start is reported instead of hanging.
- A sandboxed Hub's git no longer recurses into submodules, runs no program a workspace names, and its browser opens only http and https pages.
- Signing in to an MCP server from a browser tab now completes.
- An update neither waits for nor asks about a remote Hub.
- The Models panel reads "no provider" as an answer instead of an error.
