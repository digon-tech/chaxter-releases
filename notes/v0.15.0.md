### Highlights

- A new Dashboard gathers your work into Tasks, Planning and Todo views, with grouping, scope filters and saved views you can come back to.
- Every task now has its own page: activity, notes, links, uploads, repo commands, dev servers and its pull requests, with Merge and required checks in one place.
- A reviewer can run on its own copy of the branch at the pull request head, return a verdict, and reply to or resolve review threads.
- Jira sits beside GitHub: connect a site, bind a project, map your process to its statuses and labels, and read issues with their images.
- A console in the dock lists every running agent with memory and CPU, what it last said, and Stop, Restart and Kill.

### Features

- A new Dashboard collects your work in Tasks, Planning and Todo views, grouped by project, repository, assignee, type, provider or progress.
- Save, apply and delete Dashboard views so a filter and grouping you use often comes back.
- Filter the Dashboard by scope, and read on each card why a task wants you: a review to give, a plan waiting, a session waiting, a failed start, a setup asking for trust or an item that left its scope.
- Every task has a page with its header, activity rail, notes, links, uploads and the commands its repository offers.
- Open, follow and merge a task's pull requests from its page, with required checks shown and refreshed in the background.
- After a merge the follow-up steps run in order — worktrees cleaned up, the bound issue closed when the keyword did not — each with its receipt in the activity.
- A merge a code host's merge queue holds reads as «Queued» until it settles.
- Review a pull request from the task page, with Review and Ask, and see when a review ended with no verdict.
- Reply to and resolve a pull request's review threads, from the task page or through the agent.
- The plan pane shows a plan's revisions, takes anchored comments and an approval, and holds «Approve and implement» behind the setup's trust answer.
- Read a bound GitHub or Jira issue or pull request on the task page, its images served without handing your browser a token.
- Claim, move and release tracker items as a task progresses, following the process you set for the project.
- The Planning board reads every open item from the tracker; dropping a card on a mapped column writes the move back, and a refused drop says so on the card.
- Run a catalogue Action on a task from a split button — in one worktree, in all of them or in a new one — or launch one straight from a Todo issue.
- Create a task from the Dashboard, and rename, archive, restore, delete, retry or move it to another project from its page.
- A Worktrees view per project: see each row's tasks, chats, lock and pull request, inspect what a removal would lose, and remove or recreate a worktree.
- A task's repository commands appear as buttons, run in their own terminal, and ask for trust before an unseen script runs.
- Run a task's Playwright tests from its page, keep the run history and open a trace with its page snapshots.
- A task's dev servers are listed under it with a preview and a shared browser.
- The agent can work its own task: attach worktrees and links, start a session, run commands, open a pull request and merge it, with every write recorded in the task's activity.
- Forbidden git commands are refused on every terminal, and what the agent's own git did is reported in the transcript and the task's activity.
- Policy notices are drawn in the transcript and come back after a reload.
- A console in the dock shows every running agent with live memory and CPU graphs, its last words, how long a turn has been silent, and Stop, Restart and Kill.
- Queued follow-ups survive a restart or a crash; a queue held by a spent allowance shows its reset and offers «Send now».
- A follow-up written by someone who has left is held until a writer presses «Send now».
- A restart shows its stages in a banner, waits for idle sessions unless you force it, and the turn it cut keeps its words and a Retry.
- Preview PDF, DOCX, XLSX and PPTX files, open an image from the chat in a preview tab, and open a binary diff's file the same way.
- Comment on and screenshot the terminal, the diffs, the file viewer, the previews and the browser panel, and annotate an image before it is sent.
- Settings › Desktop shows the provisioned Bun with update and rollback, and shows git with a re-check every window follows.
- Keep-alive is a setting of its own, with a per-session override on the session menu.
- A projects settings page with its trackers surface and a process editor for review settings and tracker state maps.
- Sessions are grouped by project; rename a project from its heading and move a session to another project.
- An opt-in cloud section in Settings signs you in by a magic link, offers in-app support and lists your remote consultations of the last 30 days, read-only.
- Remote consultations run sandboxed and are mirrored as read-only sessions, marked as external.
- Every new surface reads in English and Italian.

### Bug Fixes

- Windows: the folder picker opens on the right drives, folders read correctly in the sidebar and in New session, renames the system refuses are retried, and killing an agent ends its whole process tree.
- Chaxter starts and chats with no git installed, says which git failure stopped it, and finds a git installed while it runs.
- A turn a restart interrupted now reads as interrupted, keeps the words of the prompt it cut, and shows the approvals it closed.
- A restore that never lands says the conversation did not open, and the restore clock stops while the server is unreachable.
- A session whose project folder is gone now fails naming the folder.
- Narrow windows: the Library, Settings, Preferences, agent rows and pack sheets fit at 400 px.
- An open MCP card takes its column with a single scroller and keeps its header on one line.
- Credentials in installer settings are drawn as dots, and a typed value stays out of the warning and the command line.
- Dialogs, menus and copy buttons have their own names for a screen reader.
- Images, video and audio in the desktop app draw and play again, and the first window fits the screen's work area.
- A prompt is held behind a spent allowance only where there is a release for it, and a held follow-up no longer freezes another conversation.
- The pull request cycle runs with no tab open and across a restart, and a merge made on the code host is recorded.
- A reopened pull request is seen again, and an issue a person reopened after a merge stays open.
- A task over several repositories reaches Done once its last pull request lands, and the cleanup touches only the merged repository.
- Jira: no broken query for a binding with no closed status, scope baselines are re-taken when the process or the membership kind changes, and issues link under a site's context path.
- A stopped start frees its slot, and a Retry at the cap of active tasks is refused in plain words.
- The activity rail reads every row as a sentence and no longer breaks on a kind it has not seen.
- An uninstall that was stopped says what is actually still on disk, and keeps no connection or skill on a pack it took out.
- A cancelled sign-in says who asked for it and offers it again.
- A removed connection's log is forgotten, a let-go server stays ready while its agent restarts it, and an agent's own server switch says how far it reaches.
- A chat keeps its own facts and its last-turn usage across a restart and a reload, with one session per chat in every tab.
- A failed planning drop says one true note on its card, and a task says on its card when its setup did not complete.
- The task page says why its controls are disabled in a watch-only window.
- A horizontal overscroll no longer navigates the app away.
- A PDF asks for its password in the preview panel, and Cancel stops it asking.
